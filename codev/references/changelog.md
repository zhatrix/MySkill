# 变更记录：prowler-changelog 接入

本协议用于修改 codev 自身，以及 codev 中实际发生的 spec、计划、代码修改。用户要求每项变更可追溯，
因此采用「每项逻辑变更一条」，不沿用上游 Prowler skill 的「每个 PR 一条」。没有文件修改的只读评审不造变更记录。

## 调用和项目适配

由编排器调用 `prowler-changelog`，不让只读外部 agent 写日志。有 Skill 工具时按名称调用；只有文件读取能力时，
读取环境中实际安装的该 skill 的 `SKILL.md` 并执行。安装位置由当前环境定位，不把本机插件缓存绝对路径写进通用命令。
同一批逻辑修改只需加载一次；不要为每次 Edit、每个 hunk 单独调用一个模型。

调用时明确当前目标仓库、日志路径、本次真实 diff、修改范围和下面的适配规则：

- codev 自身的源码、协议、测试和文档修改写 `codev/CHANGELOG.md`（相对 MySkill 仓库根）；若 codev 目录本身是仓库根，则写根下 `CHANGELOG.md`
- spec / 计划的回流历史默认写文档旁的 `<原文件主名>.changelog.md`；已有专用日志或用户指定位置时沿用，不新建第二份
- 业务代码修改遵循目标项目已有 changelog 布局；没有时写目标仓库根的 `CHANGELOG.md`
- 保留上游 Added → Changed → Deprecated → Removed → Fixed → Security 的分类顺序、emoji 分类标题、各分类底部追加、条目末尾不加句号、已发布记录不可改等规范；没有内容的分类不创建
- 无既定发版安排时用 `## [Unreleased]`；不套用 Prowler 的组件目录、版本号、发布标记或 GitHub PR 地址，也不擅自发版或猜版本
- 有真实 PR 时使用目标仓库的 PR 链接；无 PR 时使用变更 ID 和文件/发现编号定位，不能编造 PR 或尚不存在的 commit SHA

如果目标环境未安装该 skill，明确标注「prowler-changelog 未调用」，按本文件的已知格式完成记录；
不伪称成功调用，不自动联网安装插件。该降级只影响日志格式工具，不增加新的修改或提交授权。

## 每项记录什么

每条至少包含：日期、变更 ID、对象或文件路径、具体变化、验证状态。回流另带轮次、阶段和关联发现编号。
既有发现编号可直接用于定位；无发现编号时用日期与递增序号。编号只在当前日志内唯一，不把多个不同问题压成「若干修复」。

例如：`- 2026-09-10 [C001 / r8 回流 / r8-codex-02] spec §4.4 的审计键改为 fingerprint + fixes；待验证`

记录依据是最终 diff，不是拟修改清单。没有实施的建议不记成已完成；只完成文本同步就写「文本核对通过」，
不写「运行验证通过」。重新打开或撤回已记录项时，追加一条并引用原 ID；未发布条目的验收状态可据实更新。
日志文件自身的机械追加不递归产生新条目。

## 写入时机与核对

每批实际修改完成后、声明完成或提交前更新日志；G1、外审回流和补修分别标阶段。
记录与修改放在同一提交，沿用当前任务已有提交授权与 `codev_commit_round` 的具体文件列表限制。
纯记录不触发自动 commit；当前任务没有提交授权时保留工作区改动即可。

若修改发生在下一次外审之前，先完成日志，再制作/扫描本轮快照。外审运行期间不写日志或其它仓库文件，
避免改变 agent 正在读取的版本；已有快照因日志更新失效时重新制作和扫描，不绕过签名校验。

提交前逐项核对实际修改是否都有记录、条目是否夸大完成状态。发现漏改、未解释的改动或验收缺口，
标明未完成并处理；changelog 不能代替对最终修改的验收，也不能把 P1 改成非阻塞。

完整评审历史留在日志；当前有效决定留在 spec；下一轮仍提供相关的未关闭问题、采纳/驳回依据和真实差异。
默认不加载或内联整个 changelog，但不能借此删除 agent 必需的回归上下文。
