# codev 全库自审：第二轮

审前版本为 `3127f08`。本轮延续全库检查，重点复查异常结果、计量解析、并发持久化、意见回放和归档的组合行为。确认并修复五类问题；新增 18 项回归在旧库上为 `pass=2 fail=16`，修复后 bash、zsh 全量均为 `pass=215 fail=0`。

## 发现与修复

| ID | 级别 | 复现 | 修复与验证 |
|---|---|---|---|
| r2-01 | P1 | 结构化错误第一次 report 正确失败，正文解包成 PASS 后再次 report 却成功；前导空白或 result 对象形式也会漏掉错误标记 | 状态以带版本的 sidecar 保存，并绑定正文 SHA-256；先保存状态再替换正文，重复读取不丢失失败，新调用清除旧状态。支持前导空白、数组及对象形式。验证错误重放、成功对象、内容变化及新调用正文相同的边界 |
| r2-02 | P2 | `cost=1e-5` 被读成 `1.000 USD`；`9223372036854775807+2` 的 token 总计溢出为负数；嵌套 provider、缺项及不完整 JSON 也被误当总计 | 使用完整 JSON 顶层字段，Python 整数相加、Decimal 处理金额；缺失或非整数 token 不猜总量，成本覆盖值要求金额与币种。金额显示仍为三位小数，原始精度保留在 metrics |
| r2-03 | P1 | 一次复现中各 20 次并发写入产生 19 条坏发现行、20 条坏意见行，逐字段 printf 交错；长备注也会被切碎 | 三个账本共用独占文件锁写入完整行，字段经 stdin 传递，Tab/CR/LF 统一清洗；可捕获的写入失败在锁内撤回不完整追加。验证短记录关联字段及 8 条约 70KB 的并发长记录 |
| r2-04 | P1 | 一条有效采纳记录加一条损坏意见行，损坏行被忽略后仍输出“可进执行清单” | 校验意见行布局、枚举与主体/问题 ID；有损坏行则返回非零，保留有效历史展示但不给出执行或关闭结论。不能确定坏行归属时保守阻止整份文件用于裁决 |
| r2-05 | P2 | 同 slug、同轮次再次归档会覆盖已保存原文，也可能混入旧文件 | 先在临时目录完成复制再原子发布；同内容可重复调用，不同内容拒绝覆盖已发布轮次；结果状态 sidecar 一并归档。验证重复归档、覆盖拒绝及原文保留 |

## 最终核对

- 既有副本签名、并发母本、只读权限、扫描后漂移、Git 提交及失败恢复、超时/GC 和意见一致性测试继续通过
- bash/zsh 语法检查、`git diff --check` 通过；zsh 的沙箱 nice 提示未阻止并发子任务，字段及条数断言全部通过
- 所有复现使用临时仓库和账本，没有改写真实历史账本，没有调用真实外部模型
- 新持久化/原子归档需要 Python 3；旧会话目录里的库副本需要更新才能使用新写入协议，不能指望新锁保护仍按旧代码写入的进程
- 已有损坏历史没有自动猜测修复；完整协议迁移、跨模型缓存口径统一及真实外部 agent 流程仍属于未完成的独立工作
